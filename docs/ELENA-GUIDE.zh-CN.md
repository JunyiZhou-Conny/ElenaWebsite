# Elena：用 Codex 经营自己的网站

你不需要先读懂代码。这个仓库就是网站的可编辑原稿，GitHub 保存版本，托管平台把生成的网站展示给访客，域名是访客记住的门牌号。这三者相互关联，但不是同一件东西。

## 第一次开始

1. 接受 Conny 的 GitHub collaborator 邀请（邀请仍需 Conny 在 GitHub 发出）。
2. 在自己的电脑安装并登录 Codex，把这个 GitHub 仓库克隆到本地、作为项目打开。
3. 给 Codex 发下面这段话：

> 请阅读 README.md、AGENTS.md 和 docs/ELENA-GUIDE.zh-CN.md，启动本地网站并给我打开两个设计版本。先解释它们的区别。

如果电脑还没有 Node.js，让 Codex 协助完成环境安装。这是没有运行依赖的静态网站，不需要数据库账号或 API key。

## 平时怎么表达修改需求

提供目标、素材和真实信息即可。每次先处理一类改动，看过结果再保存。

**修改公司介绍**

> 把 LELE Films 的公司介绍改成以下文字：……。同步更新两套版本，保持当前排版。请先在本地展示结果。

**新增作品**

> 帮我添加一个 LELE Films 公司项目，片名是……，年份……，类型……，状态……。简介是……，完整署名是……，我把剧照放在……，播放链接是……。这是公司作品，不要放进我个人过往作品列表。请保留其他项目并运行检查。

**添加团队**

> 增加一位团队成员，姓名……，职务……，简介……，照片……。放在 company.team，两个版本都显示。请不要推测没有提供的经历。

**更新联系方式**

> 公司真实邮箱现在是……，请更新 company.email，并检查两个版本的邮件链接。

**只调整视觉**

> 保留所有事实和作品，把第二版蓝色调深一点，开场标题缩小一些，手机上让行间距更舒服。给我看修改前后的效果。

**检查并保存**

> 请运行 npm run build 和 npm run check，检查电脑和手机页面、图片和项目弹窗，然后告诉我修改了什么。帮我把这次确认过的修改提交并推送到 GitHub。

**更新线上预览**

> 把已经确认的改动发布到 .openai/hosting.json 对应的现有 Site，保持现有公开访问权限。不要创建新的 Site，也不要改域名。完成后给我两个链接。

这一步需要有权编辑托管站点的账号。**成为 GitHub collaborator 不会自动成为 Sites 管理员**。如果 Sites 仍在 Conny 账号里，可以由 Conny 发布，或另外把托管权限转交给你；也可以迁移到你自己的托管账户。源码不依赖 Sites，保留 GitHub 就保留了迁移能力。

## 内容如何组织

- `projects`：Elena 个人的既有作品。
- `company.companyProjects`：以后确认由 LELE Films 出品或参与的项目。结构与 `projects` 相同，`creditOwner` 写准确公司参与方式。
- `company.team`：团队成员；填入后自动显示。
- `company.services`：确认提供的商业服务；填入后自动显示，不从个人技能推断公司承诺。
- `company.email`：真实公司邮箱；空值时显示待公布说明。
- `writing`：影评、文章等外部链接。
- `settings.heroProjectId`：第二版开场使用哪个个人项目的剧照。
- `settings.showDesignSwitcher`：是否显示两版切换工具条。
- `settings.searchIndexing`：是否允许搜索引擎索引；预览阶段保持 `false`。

新增条目的字段例子在 `docs/CONTENT-TEMPLATE.json`。让 Codex 填，不必手动写 JSON。

## 素材放哪里

最终公开的精选剧照、海报、头像放 `public/images/`。所有这里的文件都可能被公开下载。

视频正片优先使用 Vimeo 或其他视频托管服务，网站里保存播放链接。相机原片、ProRes、大型素材库、合同、客户保密材料放团队自己的云盘；不要把所有工作材料都放进公开网站仓库。GitHub 适合网站源文件和经过筛选的小型素材，不是视频硬盘。

当前播放器支持 Vimeo；其他视频平台可以让 Codex 增加对应播放器。没有视频链接的项目就只展示介绍和剧照。

## 最后选定一个版本

可以告诉 Codex：

> 我选第二版作为正式网站。请把它设为首页，去掉设计比较入口和切换条，保留内容结构与原始素材。先让我看本地结果，然后准备上线。

两版是为了选方向，不必永远维护两套。如果还要保留另一版，要求 Codex 将它保存在 Git 分支即可。

## GitHub、托管、域名的最终交接

1. GitHub：Conny 添加 collaborator；以后可以转移仓库所有权到 Elena 的账户或公司组织。
2. 托管：建立 Elena 可以自己管理的账户与部署权限，确认谁能发布。
3. 内容：核对公司介绍、邮箱、团队、项目署名、照片与影片使用权限。
4. 域名：在域名注册商管理界面，按选定托管平台给出的准确记录设置 DNS。先确认根域和 `www` 的目标以及 HTTPS。当前构建没有改动 lelefilms.com。
5. 发布：上线选中的正式版本，然后打开电脑和手机检查。

域名属于谁、仓库属于谁、谁支付托管费用，是三项独立的管理责任。把它们写入公司的交接记录就不会依赖某一位朋友的电脑。

## 改错了怎么办

告诉 Codex：

> 先查看 Git 历史，找出这次修改前的版本。不要丢弃我的其他文件，帮我准备一个可以检查的回退修改。

让 Git 保存每一次已经确认的改动。不要让模型凭记忆重建旧版本。
